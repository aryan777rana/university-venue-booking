Abstract

Jaypee University of Information Technology (JUIT) manages a vast inventory of shared resources such as classrooms, boardrooms, and cultural centers. Coordinating ad-hoc room reservation requests from student representatives and faculty alongside strict academic timetables poses a continuous operational challenge. Current manual or spreadsheet-based processes lead to conflicts, double-bookings, and space underutilization.

This report details the implementation of JUIT VenueHub, an automated web-based space reservation system. The software integrates a multi-tier client-server structure, a dynamic five-day Week Availability calendar grid, real-time booking overlap warning engines, and authorization controls. Utilizing a dual-database wrapper supporting local SQLite and cloud-hosted PostgreSQL, the system is fully containerized and running publicly on Railway. Initial verification validates correct notice-period enforcement, check-in tracking, and dynamic visual conflict blocking, presenting a highly scalable model for campus facility management.

1. Introduction and Objectives

1.1 Project Background

Campus infrastructure management is a central pillar of university operations. Jaypee University of Information Technology (JUIT) schedules guest presentations, examinations, and extracurricular club gatherings daily. The coordination of these events is currently decentralized: departments approve departmental classroom usage, while the estate office manages major central infrastructure like the Open-Air Amphitheatre and the Main Auditorium. Transitioning from this fragmented layout to a modern online tracker is critical to preventing organizational bottlenecks.

1.2 Problem Statement

The lack of a unified booking dashboard results in several key issues:

  • Timetable Interruptions: Ad-hoc club activities overlap with standard academic lecture blocks, forcing class relocations.
  • Administrative Double-Booking: Inconsistencies between department approvals and estate office schedules result in multiple events booked in the same hall.
  • Lack of Real-Time Visibility: Students must physically check venue doors or contact administrators to verify availability.
  • Wasted Space Capacity: Venues booked for events that are later cancelled remain locked because there is no automated notice policy or real-time release mechanism.

1.3 Core Objectives

To address these challenges, the JUIT VenueHub system has been built with the following requirements:

  1. Day & Week View Availability: An interactive calendar interface allowing users to visually check room bookings and locks.
  2. Automatic Conflict Detection: Client and server-side checks to block overlapping schedules.
  3. Role-Based Access Control: Interfaces tailored to Student Representatives, Faculty, Department Approvers, Estate Offices, and System Administrators.
  4. Notice-Period Cancellation Controls: Automated restrictions blocking cancellations within less than a configured period (e.g. 24 hours).
  5. Simulated Attendance check-in: Check-in scanner mechanisms that mark active bookings as "Attended" and track overall campus utilization statistics.

2. Literature Review

2.1 Modern Campus Scheduling Systems

University venue scheduling is categorized under the NP-hard class of resource scheduling problems. Researchers have proposed genetic algorithms, integer linear programming, and constraint satisfaction methods. While highly academic, these algorithms are often difficult to deploy in simple web forms. Modern web-based solutions focus on building robust, real-time synchronization dashboards using REST APIs and relational databases to manage allocations dynamically.

2.2 Interval Intersection Conflict Prevention

Conflict checking checks whether a new time slot $I_{new} = [t_{start}, t_{end}]$ intersects with an existing reservation $I_{old} = [s_{start}, s_{end}]$. Mathematically, a conflict exists if:

t_start < s_end  AND  t_end > s_start

By scanning the database using SQL queries, the backend can filter out overlapping rows instantly before committing new reservations. JUIT VenueHub implements this verification on both the client (for immediate form feedback) and the server (for atomic transactions).

2.3 Database Management: SQLite vs. PostgreSQL

SQLite is a lightweight, serverless database engine that stores data in a single file. While excellent for local development, SQLite has limited support for concurrent writes and lacks advanced user management features. PostgreSQL is a powerful, open-source object-relational database system designed for high concurrency. By implementing a database-agnostic code layer in Python, JUIT VenueHub combines the best of both worlds: SQLite for offline local testing and PostgreSQL for live cloud deployment.

3. System Design & Architecture

3.1 Client-Server Communication Flow

JUIT VenueHub is structured as a Single-Page Application (SPA) communicating with a Python REST API backend. Static web assets (HTML5, CSS3, and JavaScript) are delivered by the server on initial load. Subsequent user actions (such as viewing calendar slots, submitting reservations, or approving bookings) issue asynchronous `fetch()` requests carrying JSON bodies to database endpoints.

The system stores all infrastructure and scheduling metadata using two core relational tables: `venues` and `bookings`. The relationships are maintained via foreign key constraints linking `bookings.venueId` to `venues.id`.

4. Proposed Methodology & Implementation

4.1 Five-Day Weekly Grid Rendering

The interactive calendar utilizes a grid-based CSS layout. JavaScript dynamically identifies the Monday of the selected calendar date and displays columns for Monday through Friday. It maps hourly segments (9:00 AM to 6:00 PM) for each day, checking them against standard academic locks and database records to color-code slots dynamically. Users can click any available slot to launch the booking modal with date and time parameters pre-populated.

4.2 Multi-Database Dynamic Integration

To support dynamic deployments, `server.py` implements a database connection wrapper. It checks for the presence of a `DATABASE_URL` environment variable. If found, it connects using the `psycopg2` driver; otherwise, it falls back to the local `sqlite3` module. The SQL parameters are translated dynamically from SQLite style (`?`) to PostgreSQL style (`%s`) at execution runtime. This allows seamless local development and cloud production deployment without modification.

4.3 Conflict Prevention Algorithm

Before saving any booking request to the database, the server runs a verification scan. It translates incoming requests into date and hour parameters and checks for overlaps with standard class timetables and approved events. If a conflict is detected, the server returns an HTTP `409 Conflict` status, and the client displays a scheduling warning in the form modal.

5. Results and Discussion

5.1 Real-Time Interaction and Usability

The completed JUIT VenueHub dashboard presents a modern, responsive layout. Guests can browse available rooms and calendars without authentication. Faculty and Student Representatives can log in using their emails (e.g. `rajesh@juit.ac.in` or `amit@juit.ac.in`) to check booking history logs, cancel slots, or request new reservations. HODs and the Estate Office can access the approvals panel to approve, reject, or modify pending requests with feedback comments.

5.2 Statistics and Performance

The Admin Dashboard provides real-time statistics (total active bookings, pending reviews, and check-in ratios) generated dynamically from SQL queries. It displays utilization rates using embedded SVG bar charts. The unified database connection model maintains query response times under 50ms locally and under 150ms on the cloud, verifying its suitability for campus deployments.

6. Future Scope and Conclusion

6.1 Future Expansion

In the next phase of development, we plan to implement:

  • Automatic ERP timetable sync: Integrating directly with JUIT's central academic database to fetch class block schedules dynamically.
  • Physical Smart Locks: Deploying IoT smart locks at venue doors that communicate with our API to unlock doors automatically when a user checks in via QR code.
  • Email Notifications: Automated email alerts sent to users when their booking status changes.

6.2 Conclusion

JUIT VenueHub succeeds in simplifying campus space management. By introducing real-time calendar grids, automatic conflict checking, role-based approval routing, and unified SQLite/PostgreSQL database support, the application provides JUIT with a scalable, secure, and user-friendly scheduling solution that improves facility coordination and space utilization.
